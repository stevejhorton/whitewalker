CPR+ / WhiteWalker capability inventory

Endpoint Network State Detection, Remediation, and Telemetry Framework

A truthful use-case breakdown of what CPR+ does, why it exists, and how the framework coordinates DHCP/unlock triggers, posture recovery, captive portal handling, VPN hairpin prevention, Haystack monitoring, logging, and self-update.
Prepared for architecture / operations review — Steve Horton · CPR_3.14_RC1.19

1. Executive summary

CPR+ / WhiteWalker is an endpoint-side network-state framework. It is launched by Windows Task Scheduler when a device receives a DHCP address or when the user unlocks the endpoint. The main entry point, WW_main.ps1, waits for the network stack to settle, classifies the endpoint’s real network state, and then routes to the smallest reasonable action.

Plain-English definition: CPR+ lets an endpoint answer the question, “Where am I, what network condition am I actually in, and what should I do next without making things worse?”

The framework covers more than captive portal remediation. It handles Cisco ISE posture redirect recovery, walled-garden portal detection, VPN state handling, on-prem VPN hairpin prevention, trusted SSID tie-breaking, Haystack event monitoring, syslog queueing, local diagnostics, state tracking, and gated self-update.

5. Detailed use case inventory

DHCP / unlock network state evaluation

CPR+ detects the active network context after DHCP and unlock events. It checks preflight behavior, redirect signals, adapter state, VPN state, SSID trust, and gateway/DNS conditions before deciding what to do.

ISE posture rescan automation

When posture redirect behavior is detected, CPR+ routes into the posture workflow, triggers rescan, checks service availability, monitors compliance, and verifies that network access actually recovered.

Captive portal and guest Wi-Fi

Portal handling is intentionally moved into a user-context runner. That keeps the main script from launching browsers as SYSTEM and gives the user a usable auth window.

Walled-garden networks

CPR+ distinguishes DNS-blocking portal conditions from general network failure. Gateway reachable plus DNS failure can route to the portal browser instead of dumping into a dead-end no-network state.

VPN blackhole framework

When the device is confirmed on-prem, CPR+ can apply a controlled hosts-file sinkhole for configured VPN headends. Removal is deliberately broad and safety-biased on startup, shutdown, off-prem, VPN, captive, and no-network states.

Wake and SSID-change recovery

After wake or Wi-Fi movement, VPN can appear connected while blocking the local auth path. CPR+ checks SSID changes, gives VPN a grace window, and can disconnect only when it appears stuck or harmful.

6. Haystack, syslog, and telemetry

Haystack is the event-monitoring side of CPR+. It watches for configured “needle” patterns in Windows Event Logs and writes structured hits. Those hits can be sent to syslog/Splunk when the network state says the collector should be reachable.

Important distinction: Haystack is not the root decision engine. WW_main.ps1 detects current network state and enables network-aware decisions. Haystack consumes that state so telemetry can be sent, cached, or deferred safely.

7. Safety and “do no harm” controls

CPR+ is built around conservative cleanup and cooldown behavior. The general pattern is: detect carefully, act narrowly, log clearly, and remove risky state aggressively when conditions change.

  • Blackhole removal on startup
  • Blackhole removal on all non-on-prem states
  • Shutdown task to clear VPN sinkholes before reboot
  • Trusted SSID tiebreaker before on-prem actions
  • Cooldowns for flares, rescans, updates, and syncs
  • Local cache fallback when NETLOGON is unreachable
  • Version and hash checks before config replacement
  • Size-based log rotation
  • WhatIf, debug, and trace modes
  • APIPA/no-network early exits
  • Portal and browser handling isolated into user context
  • Self-update gated by current network state

VPN hairpin / blackhole decision tree

The blackhole framework is intentionally safety-biased: only add sinkholes when on-prem is strongly supported; remove them broadly everywhere else.

Current state evaluated
Confirm on-prem and not exempt
Apply managed hosts-file sinkhole
Remove on any unsafe state

Add path

  • Device confirmed on trusted on-prem network.
  • User/device not in allow/exempt group.
  • VPN headend names mapped to localhost.

Remove path

  • Startup or shutdown.
  • Off-prem, VPN, captive portal, APIPA, or no-network.
  • Unknown state where leaving sinkhole could strand the user.

Config path

  • Sync host list and allow groups from NETLOGON.
  • Use version/hash checks and cooldowns.
  • Fall back to local cache.

Syslog / Splunk cache-and-drain decision tree

Telemetry should be useful when reachable and harmless when not. The queue keeps endpoint actions from depending on collector availability.

Telemetry event ready
Check current network state
Send now or cache
Drain FIFO when reachable

Collector reachable

  • Send structured syslog message.
  • Drain cached queue in order.

Collector unreachable

  • Write to local queue.
  • Do not block remediation.
  • Respect retention/max-entry bounds.

State-aware drain

  • Drain on on-prem, user tunnel, or management tunnel states.
  • Skip drain on captive/no-network states.
Self-update decision tree

The updater is gated so repair and rollout do not become a share-thrashing stampede.

DEV / PROD flag detected
Check network/share reachability
Apply update if eligible
Record result and cooldown

Eligible

  • Network state allows share access.
  • Cooldown permits update.
  • Pull package/config from trusted share path.

Not eligible

  • Off-net, captive, or share unavailable.
  • Leave flag/result evidence.
  • Try later when state changes.

Safety

  • Separate DEV and PROD paths.
  • Avoid loops with cooldown markers.
  • Log success/failure plainly.
FlareGun event-routing decision tree

FlareGun lets CPR+ separate detection from action, especially when an action must run in the user context instead of SYSTEM.

SYSTEM-context event

  • Telemetry, state write, update gate, or service-level action.
  • Runs without user UI assumptions.

USER-context event

11. Bottom line

Best concise description: CPR+ is an endpoint network-state remediation and telemetry framework. It reduces support ambiguity by letting the endpoint determine its real access condition, take bounded corrective action, and leave behind readable evidence for IT.

Its strongest use cases are corporate Wi-Fi / ISE posture recovery, captive portal handling, VPN hairpin prevention, wake/network-change cleanup, endpoint-side event detection through Haystack, and safer field rollout through config sync plus self-update.
