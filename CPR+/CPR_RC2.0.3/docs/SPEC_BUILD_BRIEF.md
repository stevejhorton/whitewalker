## 2. Ground rules

- ASCII only in every file (no smart quotes, no non-breaking spaces, no Unicode in code or comments).
- A spec derived from code records what the code DOES. Where the code looks wrong or
  surprising, write it in a separate "Questions for Steve" section instead of
  blessing it as a requirement. Never silently "fix" intent.
- Do not change production code in the spec pass. Findings go in REVIEW_FINDINGS.md.
  Tests may be tagged with `REQ:` ids (that is a safe edit); say so in the commit.
- Be explicit about certainty: confirmed by a test run / read in code / inferred.
- There may be no PowerShell in the session sandbox. Steve has run Pester v5.3.3 on his
  Windows box (see `docs/steve_to_review/unit_test_results_10jun26.txt`: three runs, 157/205/35
  passed with 1/7/4 failed, June 2026), but the tests added since RC2.0 have not been run
  there yet. Do not claim a test passes. Steve runs tests on a Windows box.
- Token economy: read function signatures and call graphs first (`Get-Content` with AST or
  grep on `function `), read bodies only for the area being specced, write each area to
  disk as soon as it is done so a new session does not have to re-derive it.
- Commit per area. Keep the git history intact. CPR_RC2.1 is frozen; do not edit it.

## 4. Known policies and design decisions (treat as MUST unless Steve says otherwise)

Mark "confirmed by Steve" where listed here; everything else you derive is "inferred".

- CPR never disconnects a fully Connected VPN, even on-prem. Only Connecting/Reconnecting
  are cut (early VPN gate; wake-from-sleep or SSID-jump or no usable IP). BlackHole owns the on-prem policy.
- Secure Client auto-fires a reconnect on any network change and blocks all traffic while
  Connecting/Reconnecting. It also blocks `vpncli` for minutes. Every `vpncli` call goes
  through `Invoke-VpnCliBounded` (8s query, 20s disconnect). After WW cuts the VPN in a
  run it may cut again at most `$VpnPostDisconnectRetryMax` (2) times.
- Tee levels: master `WW_tee_master.psd1`, active profile `WW_tee_events.psd1`. Flags in
  `C:\Windows\Temp`: `cpr_tee_<1-5>.flag` (reverts after 336h) and `cpr_tee_<1-5>_keep.flag`
  (sticks). 10-minute cooldown between applies (the flag waits on disk, DEBUG log only).
  Highest level wins, `_keep` wins at equal level. Pending revert keeps its original
  previous_level. Installer keeps the level and stamps reason `upgrade_kept_level`.
- Self-update: flags `cpr_update_<dev|prod>[_tee_<1-5>[_keep]].flag`. Failure count is
  written into the flag; `$SelfUpdateMaxAttempts` (5) then rename to `.failed`. A tee
  level in the name is applied only after a successful install, by dropping the matching
  `cpr_tee_*` flag for the normal handler. Off-eligible networks leave the flag alone.
- Syslog: SYSTEM appends to `logs\haystack_syslog_queue.jsonl`; non-SYSTEM writes one
  `evt_*.json` per event to `logs\spool`, ingested by HayStack. The drain claims the
  queue by atomic rename to `.draining` so entries appended mid-drain are never lost.
  Sends happen only when state.json currentState is on_prem, user_tun or mgmt_tun.
- Production message convention: action, machine, user, EvtTime (ISO 'o') first, then
  schema-known fields. Test tools use machine=CPR_TESTER.
- Log writer retries 6 times then records the loss in `logs\log_write_failures.txt`.
- The XmlVault share is reachable only on-prem or over VPN; do not attempt sync otherwise.
- Per Steve: PowerShell scripts must stay ASCII; prefer native cmdlets over regex parsing.

## 5. Review checklists

Security (the code runs as SYSTEM and reads files that users can write):
- Every file read from a user-writable location (`C:\Windows\Temp`, spool dir, handback
  files): name validation, reparse-point checks, size caps, content sanitizing, TOCTOU.
- Self-update staging in `C:\Windows\Temp` (zip and extract dir) and what is executed from it.
- Anything built into a command line or log line from external input (SSID, URLs, flag names).
- ACLs on `C:\ProgramData\WhiteWalker` and subfolders; the USER telemetry drop directory.
- Open parked items: handback `.fail` rename and 64KB cap, log sanitizing, ProgramData location TODO.

Performance and efficiency:
- Stage timings (`phase_timing` lines); repeated vpncli/netsh/CIM calls per run; fixed sleeps;
  work done in the critical path that could move to the maintenance stage.
- Known candidates: `vpncli status` when `stats` already answers; kicking HayStack at end of run
  when a queue exists and the state is reachable; hostscan bounded wait; XmlVault startup sync (13 s).

Maintainability:
- Duplicated logic between the two cap portal runners and Main; dead config (see the audit
  note in Main.Configuration.ps1); functions over ~150 lines; scopes (`$script:` vs dynamic
  scope reads like `$vpn_cmd`); static tests that should be behavior tests.

## 6. Measuring coverage (Steve runs this on a Windows box)

```powershell
Import-Module Pester -MinimumVersion 5.0
$cfg = New-PesterConfiguration
$cfg.Run.Path = '.\tests'
$cfg.CodeCoverage.Enabled = $true
$cfg.CodeCoverage.Path = @('.\main\*.ps1','.\WW_*.ps1','.\haystack_action.ps1','.\install.ps1')
$cfg.CodeCoverage.OutputFormat = 'JaCoCo'
$cfg.CodeCoverage.OutputPath = '.\coverage.xml'
Invoke-Pester -Configuration $cfg
```
Static tests will not move line coverage. Report line coverage and requirement coverage separately.
