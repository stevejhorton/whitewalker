Tech Action Console Manual

How to use Invoke-WhiteWalkerAction.ps1 to restore, refresh, update, and debug WhiteWalker (CPR+) on an endpoint without editing files by hand.

CPR 3.14.0_RC2.0.3Console 1.0.0Windows PowerShell 5.1Needs an elevated or ASAM Powershell prompt

Start here

The console is a numbered menu. Pick an action, answer the prompts, and confirm with y. Pressing Enter on any prompt that offers it cancels with nothing changed. A failure inside an action is logged and drops you back at the menu, so the console itself does not crash.

For issues or questions please reach out to: steve.horton@optum.com

Launch it

  1. Open Windows PowerShell (not PowerShell 7) with Run as administrator or ASAM_Developer. The script refuses to start without elevation.
  2. Run:
    & "C:\ProgramData\WhiteWalker\admin\Invoke-WhiteWalkerAction.ps1"
  3. The menu header shows the installed CPR version. Pick a key and follow the prompts.
Everything you do is audited.Each action writes to C:\ProgramData\WhiteWalker\logs\white_walker.admin_actions.log (1 MB, 5 files kept). If something looks wrong later, start there.
Most actions work by dropping a flag file or running a script, then waiting.WhiteWalker picks the flag up on its next run (a DHCP lease change, or locking and unlocking the screen). Nothing happens instantly unless you use Quick Action 3 (force a run).

New in RC2.0.3what changed since RC2.0.2

  • Needle bundles (menu B). Canned sets of needles for a symptom (network flap, power resume, app crashes). Pick one, choose how many days, and it is added to needles_local.cfg in one step.
  • Needles expire. A needle line can end with |expires=2026-11-13 (or a full UTC time). Expired lines are skipped and removed at the next reroll. Local needles can last at most 30 days; the wizard (menu 6) and bundles default to 14.
  • Duplicates are skipped. If two needles watch the same log, event ID and filter, the first one wins and the repeat is logged and ignored. Labels and extended-logging flags do not count.
  • Reroll offer. After the wizard or a bundle changes needles_local.cfg, the console offers to reroll HayStack right away (Y is the default).
  • Log timing (quick action 6, test only). Adds [+ms | elapsed] to every main-log line so slow steps stand out. Also available as WW_main.ps1 -WWTiming.
  • Faster network snapshot (soak). A fast in-process probe now runs beside the old cmdlet path and logs net_probe_parity=ok (or DIFF with the fields that differ). The old result is still the one used until $NetProbeMode in Main.Configuration.ps1 is switched from parity to fast.
  • Run, then watch. Items 1 and 2, 3 (self-update) and quick actions 1 and 3 now show the relevant log while they work, then return you to the menu.
  • One source for shared settings. The installer reads the version, task folder and default tee level from main\Main.Configuration.ps1 instead of keeping its own copies. A package missing that file now fails the install loudly.

What do I do when...?type a symptom or pick one

The console, item by itemread-only items are marked

1VPN Profile Restore CHANGES THINGS
Use when
The Secure Client VPN profile XML is missing, damaged, or wrong, and you want the saved good copy put back.
What it does
Creates C:\Windows\Temp\xml_restore.flag. On the next WhiteWalker run it restores the profile XML from the local vault into the VPN client profile folder.
You'll be asked
"Create the restore flag now? (y/n)"
Then
Lock and unlock the screen (or log off and on) to let the restore run. The console also offers to follow the XmlVault log; answer y to watch it and return to the menu.
Verify
Check C:\ProgramData\WhiteWalker\logs\white_walker.xml_vault.log for the restore entry.
Restores from the local vault only.If the vault copy is stale or missing, run item 2 first to refresh the vault from the share (needs the corporate network or VPN).
2Force XmlVault Sync CHANGES THINGS
Use when
A new or fixed profile XML was published to the share and you do not want to wait for the 24-hour sync cooldown.
What it does
Runs WW_xml_vault.ps1 -Force right now, in your window, refreshing the local vault from the NETLOGON share.
You'll be asked
"Force a vault sync now? (y/n)"
While it runs
The last 15 lines of the XmlVault log are shown, then you return to the menu.
Verify
white_walker.xml_vault.log. If the share is unreachable (off network, no VPN) the sync cannot complete.
3Self-Update Trigger CHANGES THINGS
Use when
You need this machine to pull a new CPR build from the share now: a test box on DEV, or a stuck box on PROD.
What it does
Creates an update flag in C:\Windows\Temp. On the next run (and only when the network and share are reachable) WhiteWalker installs the build and logs the result.
  1. Channel: 1 = DEV, 2 = PROD.
  2. Tee level (optional): 1 to 5 sets the log level after a successful update. Press Enter to leave the level alone.
  3. Keep that level? [y/N]: only asked if you chose a level. y makes it stick; otherwise it reverts on its own.
  4. Confirm. The console shows the exact flag it is about to create.

The flag name encodes your answers. Examples:

FlagMeans
cpr_update_dev.flagUpdate from DEV, leave the tee level alone
cpr_update_prod_tee_3.flagUpdate from PROD, then set level 3 (reverts later)
cpr_update_dev_tee_5_keep.flagUpdate from DEV, then set level 5 and keep it
Verify
C:\ProgramData\WhiteWalker\logs\white_walker_install.log. A successful install with a tee request logs that it dropped the tee flag; a failed install sets no level.
If it fails
It retries on later runs, up to a limit. A flag with an invalid name is renamed .failed and logged.
Why combine them?If the update fails, the tee level is not changed, so you never end up debugging on a half-updated box with the wrong log level.
4Tech Check-In SENDS TELEMETRY
Use when
You want a marker in Splunk that a tech touched this machine, usually tied to a ticket.
What it does
Queues a tech_checkin event locally. HayStack ships it to Splunk on its next wake (a lock/unlock, or the HayStack_Monitor heartbeat). It is not in Splunk immediately.
You'll be asked
An optional short note (for example ticket #12345), then "Send check-in now? (y/n)"
If it fails
The console prints the reason and a plain-English hint, and logs it to the admin log.
5Needles Sync Check READ-ONLY
Use when
You want to know whether this machine's HayStack needles match the share copy.
What it does
Compares the local needles.cfg to the NETLOGON copy (version line first, then a file hash). It changes nothing.
Results
In sync, Out of sync (HayStack's own reroll will pick it up, or use Quick Action 1), or Share unreachable.
6New Needle Wizard CHANGES THINGS
Use when
HayStack should watch for something it does not watch for today, on this machine.
What it does
Builds one needle line, validates it against HayStack's own rules, and appends it to needles_local.cfg. It never touches the share-managed needles.cfg. Local entries win if a label collides with the share copy.

Pick the type, then answer its prompts. Labels must have no spaces and none of \ / : * ? " < > |.

TypeWatches forPrompts
NEEDLEAn Event Log eventLogName, numeric EventID, optional XPath filter, Label, optional ExtendedLogging (0, 1, 2, all)
SESSIONA session state changeStateChange (SessionLock, SessionUnlock, RemoteConnect, RemoteDisconnect, ConsoleConnect, ConsoleDisconnect), Label
DEFENDERAn MDM firewall ruleRuleNameMatch (a literal, case-insensitive substring), optional IntervalHours, Label, optional ExtendedLogging
HEADERA run-header fieldFieldName (ww_version, os, model, serial, last_boot, csc_version, csc_source, vpn_profile, or *), Label, optional RefreshHours

Expiry. After the type-specific prompts you are asked how many days to keep the needle (1–30, Enter = 14). The line is written with |expires=<UTC time>; once that passes, HayStack skips it and removes it from needles_local.cfg at its next reroll. To keep a needle permanently, promote it into the share needles.cfg instead.

Reroll. When the line is written you are asked Reroll HayStack now so it picks this up? [Y/n]. Enter or y runs the reroll and shows HayStack's log as it works; n skips it (handy when adding several needles in a row).

It only takes effect after a HayStack reroll.Say yes to the prompt, wait for the next automatic one, or use Quick Actions → 1 (Force HayStack reroll). To preview what a NEEDLE or DEFENDER line will match before you commit it, use Diagnostics (8): New-NeedlePreview.ps1 or New-DefenderNeedlePreview.ps1.
BNeedle Bundles CHANGES THINGS
Use when
You are chasing a class of problem (network bouncing, sleep/wake trouble, app crashes) and want a ready-made set of needles on this machine, not one at a time.
What it does
Lists the bundles in the catalog (bundles\needle_bundles.cfg; the share copy is used when reachable, the packaged copy otherwise), shows how many needles each has and how noisy it is, then writes the chosen bundle into needles_local.cfg with every line set to expire. It never touches needles.cfg.
You'll be asked
The bundle number, how many days to keep it (1–30, Enter = the bundle's default, usually 14), a confirmation, then whether to reroll HayStack now (Enter = yes).

Re-applying a bundle replaces its lines and restarts the clock. R removes a bundle that is applied on this machine. Bundled needles are labelled bundle.<name>.<label>, so they are easy to spot in haystack.log and Splunk. If a bundled needle matches the same event as one already in needles.cfg or another bundle, HayStack keeps the first and logs the skip; nothing breaks.

The catalog is checked every time.If it has a problem (a line HayStack's parser rejects, a repeated label), the tool lists the problems and applies nothing.
7Tee Log Level Picker CHANGES THINGS
Use when
You need more (or less) of WhiteWalker's detail going to the logs and Splunk for an investigation.
What it does
Regenerates the active tee profile (WW_tee_events.psd1) at the level you choose, built from the master file.
You'll be asked
Pick a level number from the list, then "Overwrite the active tee profile now? (y/n)". Enter cancels.
If you see "active profile is STALE".The active profile no longer matches the master. Use T (below) to rebuild it without changing the level.

See Tee log levels for what each level sends. Higher levels mean more log volume; go back down when you are done.

TRefresh Active Tee Profile CHANGES THINGS
Use when
The picker warned the profile is stale, or events that should be logging at your level are missing.
What it does
Compares the active profile with the master for your currently selected level, lists missing or unsupported tags, and (after you confirm) regenerates it. It never changes the level. If it cannot tell which level is selected, it leaves everything alone and tells you to use the picker.

Flag filesthe "touch a file to ask WhiteWalker" mechanism

WhiteWalker looks in C:\Windows\Temp at the start of each run. A flag file is an empty file with a meaningful name. The console creates these for you, but you can also create one by hand.

FlagEffect
cpr_tee_N.flag (N = 1 to 5)Set tee level N. Reverts on its own after 336 hours (14 days).
cpr_tee_N_keep.flagSet tee level N and keep it (no automatic revert). If both exist at the same level, _keep wins.
cpr_update_dev.flag / cpr_update_prod.flagSelf-update from that channel. DEV wins if both exist.
cpr_update_<dev|prod>_tee_N[_keep].flagUpdate, then set tee level N (kept if _keep) only if the install succeeded.
xml_restore.flagRestore the VPN profile XML from the local vault on the next run.
Tee flags have a 10-minute cooldown.A tee flag can be held back for about 10 minutes by a cooldown. The flag stays on disk and is applied once the cooldown passes, so a flag you just created may not act on the very next run.

Create one by hand

New-Item C:\Windows\Temp\cpr_tee_5_keep.flag -ItemType File -Force
New-Item C:\Windows\Temp\cpr_update_dev_tee_5_keep.flag -ItemType File -Force

See what is waiting

Get-ChildItem C:\Windows\Temp\cpr_*.flag, C:\Windows\Temp\xml_restore.flag -ErrorAction SilentlyContinue | Select Name, LastWriteTime

Tee log levelshow much WhiteWalker reports

LevelNameWhat it sends
0MINIMALOnly tee level reporting. Nothing else leaves the box.
1CORE DEFAULTFleet health, VPN/ISE, captive portal including the whole flare lifecycle, XmlVault, self-update.
2CORE + NETWORKAdds per-run network state and SSID changes.
3+ POSTURE DETAILAdds posture detail, MAC randomization, trusted SSID.
4RESERVEDCurrently identical to level 3.
5EVERYTHINGDebug and incident investigation. Highest volume.
Rules of thumb.Use 1 for normal life. Use 3 for most VPN or captive portal troubleshooting. Use 5 only while you are actively reproducing something, then drop back. When several flags exist, the highest level wins.

Troubleshooting

"Requires elevation" or the script will not start

Close the window and reopen Windows PowerShell with Run as administrator. The console needs Windows PowerShell 5.1, which is the default powershell.exe.

"... not found at C:\ProgramData\WhiteWalker\..."

That script is not installed on this machine, or WhiteWalker is not installed. Check C:\ProgramData\WhiteWalker. A missing item only affects that action; the console carries on.

I created a flag but nothing happened

Flags are read on the next WhiteWalker run. Lock and unlock the screen, or use Quick Action 3. For tee flags, remember the 10-minute cooldown. For update flags, the machine must reach the share (corporate network or VPN). Check the install log for the result.

The menu looks older than this manual

The new build has not reached this machine yet. Trigger a self-update (item 3) and check the install log. The header shows the installed CPR version.

"Share unreachable" on sync, update, or needles check

The NETLOGON share is only reachable on the corporate network or over VPN. Connect, then try again.

"Action failed: ..." in red

The error was caught and logged to the admin log. Read the message, fix the cause (usually a missing file or an unreachable share), and retry. Send the line from white_walker.admin_actions.log if you escalate.

The check-in did not show up in Splunk

A check-in is only queued locally. It ships on HayStack's next wake. If it still does not arrive, run Quick Action 5 (Syslog path test) to see where the path breaks.
